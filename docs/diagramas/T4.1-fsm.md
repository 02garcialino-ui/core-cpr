# T4.1 — Máquina de estados (FSM): diagnóstico y compresión

> Diseño de la lógica de decisión (Fase 4). Sin motor todavía — la salida de "comprimir" es un LED de prueba (T4.5). El control real del motor se programa en la Fase 5.

## Estados

- **MONITOREANDO** — paciente con pulso. No se hace nada, solo se observa.
- **COMPRIMIENDO** — no hay pulso. El dispositivo actúa (LED por ahora, motor en Fase 5) durante 2 minutos seguidos.
- **REEVALUANDO** — pausa de 5 segundos dentro del ciclo de compresión, para volver a revisar al paciente.
- **DETENIDO_EMERGENCIA** — alguien presionó el botón de paro. Se llega aquí desde cualquier estado, en cualquier momento.

## Diagrama

```
                         ┌────────────────────────────┐
                         │  BOTÓN DE EMERGENCIA         │
              (desde cualquier estado, en todo momento) │
                         └──────────────┬───────────────┘
                                         ↓
[ARRANQUE] → [MONITOREANDO] ⇄ ...  [DETENIDO_EMERGENCIA]
                  │  ↑                (sale con reinicio manual — se define en Fase 7)
        lee ECG (log) + PPG (decide)
                  │  │
        pierde pulso │ recupera pulso (detectado en REEVALUANDO)
                  ↓  │
           [COMPRIMIENDO] ── 2 min ──→ [REEVALUANDO]
             lee fuerza + profundidad       │ pausa 5s
             (control, ~5cm, ≤250N,         │ lee ECG (log) + PPG (decide)
              100-120 CPM)                  │
                  └──── sigue sin pulso ─────┘
```

## Regla de decisión: el PPG tiene la última palabra

Se consideró usar el ECG, el PPG, o ambos cruzados para decidir "vivo/paro". Se eligió que el **PPG decida siempre**, tanto para empezar como para detener las compresiones, por el caso clínico de **Actividad Eléctrica Sin Pulso (AESP)**: el corazón puede mostrar actividad eléctrica organizada en el ECG sin estar bombeando sangre de verdad. Si el ECG pudiera detener las compresiones, el dispositivo podría parar creyendo que el paciente está bien, cuando en realidad no hay circulación real.

El ECG se sigue leyendo y registrando en los logs (útil para detectar y documentar un caso de AESP), pero no participa en la decisión final.

## Por qué no se lee ECG/PPG durante la compresión activa

El movimiento físico de las compresiones distorsiona ambas señales (a esto se le llama "artefacto de movimiento"). Ni siquiera el ECG es confiable en ese momento con el hardware simple de este proyecto (sin filtros avanzados). Por eso, durante los 2 minutos de COMPRIMIENDO, no se lee ningún sensor de diagnóstico — recién se vuelve a revisar en la pausa de 5 segundos de REEVALUANDO, cuando el sistema está quieto. Esto además coincide con la práctica real (AHA/ACLS limita las pausas para revisar el pulso a un máximo de ~10 segundos).

## Por qué sí se leen fuerza y profundidad durante la compresión

El HX711 (fuerza) y el VL53L0X (profundidad) son sensores de **control**, no de diagnóstico — su función es medir el movimiento mientras ocurre, para corregirlo en tiempo real (lograr ~5 cm de profundidad, no pasar de 250 N, mantener 100-120 compresiones por minuto — valores ya definidos en `config.h`). No sufren el problema del artefacto de movimiento porque su trabajo es justamente medir ese movimiento.

## El botón de emergencia

Se agrega como una transición global: desde cualquier estado, en cualquier momento, puede llevar a **DETENIDO_EMERGENCIA**. El detalle de cómo se sale de ese estado (reinicio manual, un botón de "reanudar", etc.) se termina de definir en la Fase 7 (T7.1, módulo de seguridad) — aquí solo queda marcada la transición de entrada.

## "Plan B": cambiar el criterio de decisión si el PPG da problemas

La decisión "¿hay actividad vital?" va a vivir encerrada en una sola función dentro de `logica_fsm.cpp` (mismo patrón de "doble capa" que ya se usa para `MODO_SIMULACION`). Si en algún momento hace falta volver a un criterio basado solo en el ECG, el cambio sería modificar el contenido de esa única función — el resto del sistema no se toca. No se implementa un interruptor en `config.h` para esto a menos que se pida explícitamente.

## Cómo se prueba

| Escenario | ECG (Arduino) | PPG (dedo real) | Resultado esperado |
|---|---|---|---|
| Normal | activo | puesto | vivo, no comprime |
| Paro clásico | cortado | retirado | comprime |
| AESP (caso especial) | activo | retirado | comprime igual (demuestra que manda el PPG) |

## Nota honesta

El sensor PPG real (MAX30102) es un sensor óptico que necesita tejido con sangre circulando de verdad — no se puede simular con un potenciómetro como el ECG. Por eso la prueba en físico usa un dedo real en vez de un control eléctrico. Para la prueba final sobre el maniquí (T10.1), esto sigue siendo un tema abierto: un maniquí no tiene pulso real, así que probablemente haga falta un dedo humano cerca del sensor durante la demostración. La idea de fabricar un "pulso falso" automático (ej. con una luz parpadeante calibrada) queda anotada como posible mejora a explorar más adelante, sin garantía de que funcione — no se ha probado con el chip real.
